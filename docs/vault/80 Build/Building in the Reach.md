# Building in the Reach

The Reach is generated by the plugin. A good design has to survive chunk boundaries, terrain variation and gameplay placement. Use [[Technical Plan]] for design intent. Use the working tree for actual feature names, dimensions and test behavior. Paths below start at the repository root.

| Need | Start here | Design implication |
| --- | --- | --- |
| Locate a site | `nerdsmp-paper/src/main/java/net/nerdsmp/paper/reach/ReachTerrain.java`, `ReachPath.java`, `ReachBuilds.java` in the same package | Sample the footprint, approaches, water and neighboring features. Check actual reserved bounds before choosing a grade. |
| Add to a town | `HighcrownCity.java`, `HighcrownCastle.java`, `GoldenreachVale.java` | Extend the owning zone. Millbrook chooses sites against terrain and reserves house lots. Trace a similar existing placement before adding another. |
| Lay a graded kit | `ReachKit.java`, `ReachBrush.java`, `ReachCanvas.java`, `ReachInteriors.java` | Follow the kit's site grading, local orientation and floor convention. Transform the doorstep and its standing spot with the building. Include eaves, props and retaining walls in the envelope. |
| Attach foliage or road dressing | `ReachTreeGen.java`, `ReachFlora.java`, `ReachRoadside.java` | Inspect occupied columns and the route reserve. Vary by stable location so rebuilding the same site preserves its shape. |
| Publish a feature | `ReachFeatures.java`, `ReachSettle.java`, `ReachBuilds.java` | Features produce a canvas and named spots. The plan is settled and frozen once, then the generator places each chunk's slice. Include every projecting block in the declared footprint. |
| Populate and test | `ReachPack.java`, `ReachGameplay.java`, `nerdsmp-paper/src/test/java/net/nerdsmp/paper/reach/` | Resolve actual spot IDs (feature ID plus local ID), facing, floor and headroom. Check arrival, interaction, return path and existing anchors after a layout change. |

### An offline review before a world walk

From the repository root, a focused Gradle run for the current geometry checks is:

```powershell
.\gradlew.bat :nerdsmp-paper:test --tests 'net.nerdsmp.paper.reach.ReachBuildsTest'
```

Read `ReachBuildsTest` for the specific assertions. They include feature bounds, building sites, named-spot footing and headroom, sign text and arrival. Its optional `REACH_PLAN` accepts an output PNG path; `REACH_PLAN_FEATURE` selects the feature and `REACH_PLAN_BOX` takes inclusive x0,z0,x1,z1 bounds. Use an existing local output directory and force the test to rerun when requesting a fresh plan. `REACH_SPOTS` can write the spot coordinates to a local JSON file. A plan view helps locate collisions and awkward junctions. Use an in-game eye-level shot to judge an archway or skyline.

### When the task uses Architect Studio

For an explicitly scoped Architect task, follow `aerborne-architect/CLAUDE.md`, `aerborne-architect/AGENTS.md` and `aerborne-architect/docs/STUDIO.md`. Use the actual allowed world and region, preview and approval path for that workflow. A staging composition, exported schematic or dashboard preview has its own scope and provenance. For the Reach, implement accepted ideas through its generator and world content. Use [[Build Critique]] to distinguish geometry checks, real world verification and the user's visual verdict.
