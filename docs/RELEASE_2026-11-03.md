# Release checklist: 3 November 2026

What goes out tonight, how to put it live on BisectHosting, and what to check after. The two files are
`NerdSMP-Paper.jar` and `Website.zip` in the repository root, both built from the working folder.

## What's in it

- The rebuilt expeditions and the Cinder Keep raid, with every playtest fix through `a58fe04`.
- `/checkpoint` (`/stuck`) for players stuck in an expedition; staff can start any expedition alone.
- The cosmetics suite (`8e93e03`): titles, auras, finishers, three companions and three trails, a wardrobe
  with a page per kind, and server-wide XP boosters. See [COSMETICS.md](COSMETICS.md).
- **Also in the jar:** other sessions' uncommitted work in the same folder (about 280 changed or new files,
  including the metallurgy recipes the raid's crafted items use). Those files weren't reviewed for this
  release. The full test suite (1831 tests) and the website tests (210) pass with them in.

## Before

1. Take a backup in the Bisect panel: worlds, `plugins/`, and the database if you use one.
2. Keep the old `plugins/NerdSMP.jar` somewhere outside `plugins/`. It's the rollback.
3. In Tebex, reset the private key if it has ever been shared, and set the new one on the website.

## Put it live

1. Stop the server from the panel.
2. Upload `NerdSMP-Paper.jar` to `plugins/` as `NerdSMP.jar`, replacing the old one.
3. In `server.properties` set `view-distance=8`, `simulation-distance=6` and `sync-chunk-writes=false`.
   The first two match `deploy/paper/server.properties`; the last stops chunk saves stalling the main thread.
4. Start the server. On first start it upgrades the unedited sample expeditions, moves the relic catalog to
   version 16 and rebuilds each map's template the first time it runs, so the first run of each map loads slower.
5. Website: extract `Website.zip` over the app folder (don't recreate the app) and click **Restart**.
   It needs `AERBORNE_TEBEX_PUBLIC_TOKEN`, `AERBORNE_TEBEX_PRIVATE_KEY`, `AERBORNE_TEBEX_WEBHOOK_SECRET` and
   `SITE_URL`. The Tebex Project ID isn't used: the Headless API signs in with the public token and private key.

## Tebex packages to add

Each package gets the delivery command `nerdadmin entitlement grant {username} <product id> {transaction}`
and the refund command `nerdadmin entitlement revoke {transaction} Refunded`. `/nerdadmin entitlement products`
lists every id.

| Package | Product id |
|---|---|
| Glimmerbee, Bramblehog, Driftfin | `cosmetic.companion.glimmerbee`, `.bramblehog`, `.driftfin` |
| Snowdrift, Ember Wake, Glowspore trails | `cosmetic.trail.snowdrift`, `.ember-wake`, `.glowspore` |
| Skyborne, Stormchaser, Starlit, Windrider titles | `cosmetic.title.skyborne`, `.stormchaser`, `.starlit`, `.windrider` |
| Glimmer Halo, Petal Orbit, Snow Globe auras | `cosmetic.aura.glimmer-halo`, `.petal-orbit`, `.snow-globe` |
| Starburst, Confetti Pop, Soul Release finishers | `cosmetic.finisher.starburst`, `.confetti-pop`, `.soul-release` |
| XP Booster | `booster.xp`, granted once per booster bought |

The website's store and companion pages don't list the new items yet; they need their own art and store
entries. They can be sold through Tebex before then.

## After the restart

- The console starts without errors, and no "snapshot failed" lines repeat.
- `/nerdadmin releasecheck` runs. The open gates it lists (bank, starter kit, graves, campaign delivery;
  two-client and load tests) are known and unchanged by this release.
- `/cosmetics` opens the wardrobe hub; `/booster` answers.
- Grant yourself a title with a made-up transaction id (`staff-2026-11-03-test`) and wear it.
- Start an expedition and check the opening scene and the first room.
- A test checkout on the website reaches Tebex's payment page.
- Run `/spark profiler start --timeout 600 --only-ticks-over 50` once players are on, to catch the TPS dips.

## Rollback

Stop the server, put the old `NerdSMP.jar` back, restore `plugins/NerdSMP/content/relics.yml` from
`relics.yml.before-v16.bak`, and start it. Player data written by this release (new cosmetic choices,
`boosters.yml`) is ignored by the older plugin.
